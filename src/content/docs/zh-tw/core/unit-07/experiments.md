實驗不是「執行程式，看看會發生什麼」。執行前要先寫下處置、對照、指標，以及兩種結果各自如何解釋。下面的表格是一份精簡預註冊表。

| 欄位 | 執行前要回答的問題 |
|---|---|
| 假設 | 你預期哪個方向或數值？理由是什麼？ |
| 實驗單位 | 文件對、保留故事、種子，還是整次訓練？ |
| 處置與對照 | 只有哪一項決策改變？ |
| 固定預算 | 詞元、更新次數、模型、最佳化器與評估是否固定？ |
| 主要指標 | 哪一個數字直接回答問題？ |
| 不確定性 | 二項區間、配對故事自助法、種子間變異，還是三者都要？ |
| 失敗含義 | 預測失敗時，先檢查哪項假設？ |

標準檔案是 [`spine/stage07_pretrain.py`](https://github.com/yhxuee/deep-learning-intelligent-systems/tree/main/spine)、`spine/data/make_tales.py` 與 `spine/data/tales_manifest.json`。進行介入實驗時，把生成語料與檢查點寫入暫存目錄；不要默默取代標準語料，或後續單元使用的階段 07 檢查點。

## 實驗 7.1——用植入的標準答案稽核偵測器

**問題。** 在哪些語料種子下，階段 07 偵測器能找回植入的精確副本、近似副本與保留集副本，同時不把未植入配對誤標出來？

**預測。** 精確雜湊應找回所有正規化後的精確副本。植入的保留集副本，其方向性 8-gram 覆蓋率應為 $1$。MinHash 的近似重複召回率應很高，卻不必恰為 $1$，因為分帶具有隨機性，一字編輯也會產生一段範圍的 Jaccard 值。

**實驗單位。** 召回率以一組植入配對為單位；誤報檢查則以一組未植入候選配對為單位。

**步驟。** 對種子 $2027,2028,2029,2030$：

1. 在記憶體或暫存目錄中呼叫 `make_tales.build(seed)`；
2. 保留該種子傳回的 manifest 作為標準答案；
3. 依 `held_out_start` 切分，只在訓練集執行精確與近似去重，再做方向性污染評分；
4. 把偵測配對與訓練副本索引和 manifest 比較；
5. 對每一個額外標記，先查看精確 Jaccard 與原文，再稱為誤報——模板生成可能意外產生未植入但真正相似的副本。

**記錄。** 分開記錄精確副本召回率、近似副本候選召回率、套用 $J\ge0.7$ 後的最終近似召回率、$C_8\ge0.8$ 的污染召回率、額外標記數，以及最大的乾淨保留分數。除了比例也要報數量；「6/6」比「100%」更有資訊。

**失敗解釋。** 漏掉精確副本代表實作或正規化錯誤。漏掉近似副本可能發生在最終門檻前（沒有 LSH 碰撞）或門檻後（真實 Jaccard 小於 $0.7$），要把兩者分開。額外污染標記可能是偵測器誤報，也可能是生成器的意外碰撞；只看 manifest 無法判斷後者，必須檢視原文。

## 實驗 7.2——量測 LSH 的 S 形曲線

**問題。** 實際候選機率是否吻合

$$
P_{\text{cand}}(J)=1-(1-J^r)^b?
$$

**預測。** 若雜湊列彼此獨立隨機，觀察比例應在二項抽樣誤差內吻合公式。總列數同為 64 時，$(b,r)=(32,2)$ 應比 $(16,4)$ 提出更多低相似度配對。

**步驟。** 選擇至少含 1,000 個符號的全集。對每個目標 $J\in\{0.1,0.2,\ldots,0.9\}$，建立 2,000 組交集與聯集大小已知的集合對，並記錄其**實際** Jaccard 值；整數集合大小未必能精確實現指定小數。產生獨立 MinHash 排列，或清楚記錄使用的有種子近似。測試 $(16,4)$ 與 $(32,2)$，但總列數都維持 64。

每個點都要畫出：

- 理論候選機率；
- 實際候選比例；
- 95% 二項區間，例如 Wilson 區間。

**合理性計算。** 在 $J=0.7$ 時，$(16,4)$ 預測

$$
1-(1-0.7^4)^{16}\approx0.988.
$$

若有 2,000 組獨立配對，二項標準誤約為

$$
\sqrt{0.988(1-0.988)/2000}\approx0.0024.
$$

**失敗解釋。** 系統性不吻合可能表示各列相關、簽章切分錯誤，或混淆了「同一個 band」與「同一列」。同時檢驗許多點時，單一點落在名目 95% 區間外並非不可能；要查看整條曲線，而不是由一個點宣告失敗。

## 實驗 7.3——隔離訓練集去重的效果

**問題。** 在固定計算量下，移除訓練副本如何改變乾淨保留集 NLL？

**預測。** 符號不保證固定。去重會移除意外的過度加權，也讓固定詞元預算看見更多唯一範例；但重複也可能幫助模型學會常見模板。只有在檢查副本類別內容之後，才能預註冊有方向的預測。

**處置。** 去重後的訓練故事。**對照。** 原始訓練故事。兩邊都必須保持同一保留切分，並移除污染保留集的訓練副本；否則實驗會把去重與評估洩漏混在一起。

**控制。** 使用相同架構、初始參數種子、最佳化器、更新次數、批次大小、上下文長度、詞彙表與評估故事。至少執行三個配對訓練種子。「相同 epoch 數」不是固定計算量控制，因為資料集大小不同；應固定抽樣詞元量或更新次數。

**主要指標。** 對種子 $s$ 與保留故事 $i$，記錄每字元 NLL：$L^{\text{raw}}_{s,i}$ 與 $L^{\text{dedup}}_{s,i}$。把改善定義為

$$
\Delta_{s,i}=L^{\text{raw}}_{s,i}-L^{\text{dedup}}_{s,i},
$$

所以正值支持去重。報告平均值、配對故事層級分布與種子間變異。對故事做自助法估計的是題目不確定性；三個種子不足以精確描述訓練執行不確定性，因此要明列三個種子的估計值。

**失敗解釋。** 區間包含零，表示此實驗以目前檢定力無法判定符號，不代表兩套程序完全相同。若看到很大增益，必須先確認詞彙表、去污染、更新次數與檢查點選擇都相同，才能稱為因果結果。它也不能直接與詳解例題 7.8 中同時改變多項因素的階段 04—07 差異相比。

## 實驗 7.4——植入並量測記憶

**問題。** 在固定訓練計算量下，重複是否提高序列專屬概似與精確重現？

**設計。** 訓練前，依與模型結果無關的規則選出六篇保留故事與六篇配對對照故事。建立暫存訓練集，把每篇指定故事插入 $m\in\{0,1,5,20\}$ 次。這些是刻意污染的實驗資料；絕對不能把它們的分數當成誠實的模型評估。

以相同詞元／更新預算訓練配對種子。對故事 $i$ 量測：

1. 完整故事 NLL；
2. 給定固定 40 字元前綴後的後綴 NLL；
3. 貪婪續寫與原文相同的最長前綴；
4. 在數個預註冊前綴長度與抽樣種子下的精確重現率。

一個有用的對比是差中差。令 $P$ 表示植入故事、$C$ 表示配對對照、$m$ 表示副本數、$0$ 表示乾淨執行：

$$
\Delta_m=
[(L_{P,m}-L_{P,0})-(L_{C,m}-L_{C,0})].
$$

植入故事的 NLL 下降時，$\Delta_m$ 為負。查看結果前就要先聲明這個符號約定。

**預測。** 更多副本通常應降低植入故事的 NLL，並增加精確續寫。但每個種子的反應不必單調：最佳化雜訊、被排擠的其他訓練範例，以及共同模板，都可能模糊只有六個題目的估計。

**失敗解釋。** 沒有貪婪精確吻合，不代表沒有記憶；NLL 仍可能改變。插入一次後出現精確吻合，也不能建立普遍的一次學習定律；故事可能高度模板化，即使沒有副本也可預測。必須和配對對照及 $m=0$ 模型比較。

## 實驗 7.5——不偷換問題地比較自迴歸與遮罩目標

**問題。** 在配對計算量下，目標如何改變下一字元預測與凍結表示品質？

**模型。** 在形狀允許處使用相同寬度、深度與參數初始化。自迴歸模型採因果注意力，在幾乎所有位移位置都有損失；遮罩模型採雙向注意力，選取 15% 位置並預測原字元。除了最佳化更新次數，也要報告目標預測總數；相同步數不代表相同監督目標數。

**評估。** 使用三欄，而不是宣告一個含義不明的贏家：

1. **原生驗證損失：**AR 下一字元 NLL 與遮罩重建 NLL，並清楚標記兩者單位不可直接比較；
2. **共同末字測試：**隱藏最後一個字元、不提供右側上下文，讓兩個模型都評分；
3. **凍結探針：**以相同數量訓練範例擬合相同正則化探針，再在未見故事模板上測試「是否含算術」與「寫出的答案是否正確」。

探針正則化要用探針驗證切分選擇，不能偷看最終保留集。報告類別平衡、準確率與機會／多數類別基準。「是否含算術」可能只靠淺層詞彙線索就能解，因此更難的正確性探針是伴隨檢查，而不是推理能力證明。

**預測。** AR 直接針對共同末字介面訓練，所以具有目標對齊優勢。遮罩模型在預訓練時可看兩側，可能有利於某些全故事探針。在這個小規模下，兩種結果都不保證。

**失敗解釋。** 探針差異可能來自目標、注意力遮罩、目標損失數量或最佳化，而不只是目標本身。這個實驗比較的是兩套完整訓練配方。若要更嚴格的因果主張，還要加入每次只改一個元件的消融。

## 實驗 7.6——重現標準階段 07 產物

**問題。** 目前簽入的管線，是否仍能重現資料清理不變量與已儲存檢查點的指標？

從儲存庫根目錄先執行不覆寫產物的驗證：

```bash
.venv/bin/python -m pytest spine/test_spine.py -k stage07 -q
.venv/bin/python spine/stage07_pretrain.py --steps 4000 --no-save
```

`--no-save` 可避免探索性執行取代 `spine/checkpoints/stage07.npz`。已簽入檢查點的詮釋資料記錄 4,000 次更新，以及每字元約 $0.242$ nat 的保留 NLL。只有當程式、資料、數值函式庫與種子相同，附近數值才能作為重現目標；同時要記錄精確 commit 與環境。

**必要證據。** 保存：

- 清理前後的副本與污染數；
- 清理後保留集重疊的最大值與中位數；
- 完整訓練損失日誌，而不只是最後一行；
- 最終保留 NLL 與實際耗時；
- 命令、commit 雜湊與軟體版本。

**驗收條件。** 測試必須為標準 manifest 找回所有植入項目；清理後每個保留污染分數都低於 $0.8$；訓練過程不得出現非有限值。近似 NLL 目標檢查的是可重現性，不是數學不變量，也不是每項能力都進步的證據。

只有在產物通過驗收之後，它才應成為單元 08–12 抽樣、後訓練、評估與拆解的檢查點。這個順序能讓後續結論綁定到同一個可稽核模型，而不是碰巧最近執行的那一個。

## 實驗報告模板

每個實驗都依下列順序報告：

1. 預註冊預測與符號約定；
2. 處置、對照與所有固定項；
3. 原始計數或逐項數值；
4. 帶不確定性的彙總；
5. 標明種子與單位的圖；
6. 哪種結果原本會改變你的結論；
7. 本實驗**沒有**建立的一項主張。

最後一行是結果的一部分，不是事後補上的免責聲明。
