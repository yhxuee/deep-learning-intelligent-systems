## 詳解例題 9.1——精確的策略梯度

**設定。** 三個動作，logits $z = (0, 0, 0)$，所以 $\pi = (\tfrac13, \tfrac13, \tfrac13)$；獎勵 $r = (1, 0, 0)$。

**梯度。** $\partial J/\partial z_k = \pi_k(r_k - \pi^{\top}r)$，其中 $\pi^{\top}r = \tfrac13$：$(\tfrac13\cdot\tfrac23,\ \tfrac13\cdot(-\tfrac13),\ \tfrac13\cdot(-\tfrac13)) = (0.2222, -0.1111, -0.1111)$。

**解讀。** 被獎勵之動作的 logit 上升的量，是其他每個 logit 下降量的兩倍，且各分量總和為零——對所有 logits 加上同一個常數不會改變任何事。主幹專案的測試抽出 400 000 個動作，檢查 REINFORCE 的平均在 0.004 以內重現這個向量。

## 詳解例題 9.2——基準的作用

**設定。** 詳解例題 9.1，每次估計只用一個樣本，看 $\hat g = (r_a - b)(e_a - \pi)$ 的第 1 個分量。

| 基準 $b$ | 若 $a = 1$ 的 $\hat g_1$ | 其他情況的 $\hat g_1$ | 平均 | 變異數 |
|---|---|---|---|---|
| 0 | $1\cdot\tfrac23 = 0.667$ | $0$ | 0.2222 | 0.0988 |
| $\pi^{\top}r = \tfrac13$ | $\tfrac23\cdot\tfrac23 = 0.444$ | $(-\tfrac13)(-\tfrac13) = 0.111$ | 0.2222 | 0.0247 |

**解讀。** 平均相同，變異數只剩四分之一。沒有基準時，沒得到獎勵的樣本不帶任何訊號；有了基準，它們會把自己的動作往下推，這也是資訊。

## 詳解例題 9.3——傾斜的最佳解

**設定。** 參考分布 $\pi_{\text{ref}} = (0.2, 0.5, 0.3)$，獎勵 $r = (1, 0, 0)$。命題 9.1 給出 $\pi^\star\propto\pi_{\text{ref}}e^{r/\beta}$。

| $\beta$ | $\pi^\star$ | 最佳值 $\beta\ln Z$ |
|---|---|---|
| 0.1 | (0.9998, 0.0001, 0.0001) | 0.839 |
| 0.5 | (0.6488, 0.2195, 0.1317) | 0.412 |
| 2.0 | (0.2919, 0.4426, 0.2655) | 0.244 |

**解讀。** 在 $\beta = 0.5$ 時，被獎勵之動作的勝算乘上 $e^{2} = 7.39$；沒被獎勵的動作保留參考分布中 5 : 3 的比例。大的 $\beta$ 幾乎不移動參考分布；小的 $\beta$ 趨近獎勵的 argmax，並忘掉參考分布所知道的其他一切。

## 詳解例題 9.4——手算貝爾曼方程式

**設定。** 從狀態 A 出發，唯一的動作以獎勵 0 通往狀態 B；從 B 出發，回合以獎勵 1 結束。折扣 $\gamma = 0.9$。

**價值。** $V(B) = 1$；$V(A) = 0 + 0.9\cdot V(B) = 0.9$。若 A 還有一個獎勵為 0、回到 A 的「停留」動作，最佳性方程式 $V(A) = \max(0.9\,V(B),\ 0.9\,V(A))$ 仍給出 $V(A) = 0.9$：永遠等待的價值是 $0.9^k\to0$，絕不會比前進更多。

**解讀。** 折扣使延遲的獎勵價值較低，而貝爾曼方程式一步一步地把價值往回傳——這是時間反向傳播（單元 05）在動態規劃中的對應。

## 詳解例題 9.5——偏好的數值

**Bradley–Terry。** 若 $r(y_w) - r(y_l) = 1$，則 $P(y_w\succ y_l) = \sigma(1) = 0.7311$，該配對的獎勵模型損失為 $-\ln0.7311 = 0.3133$。

**初始化時的 DPO。** 當 $\pi = \pi_{\text{ref}}$，邊際 $u = 0$，每個配對的損失都是 $\ln2 = 0.6931$。

**一步之後。** 若策略已把 $\pi(y_w)/\pi_{\text{ref}}(y_w)$ 加倍、把 $\pi(y_l)/\pi_{\text{ref}}(y_l)$ 減半，則在 $\beta = 0.1$ 時，$u = 0.1(\ln2 + \ln2) = 0.1386$，損失為 $\ln(1 + e^{-0.1386}) = 0.6262$。

**解讀。** DPO 隱含的回應獎勵，是 $\beta$ 乘上該回應相對於參考的對數機率比；損失只在乎兩個回應之比值的*差*。

## 詳解例題 9.6——後訓練主幹模型

**設定。** 400 個留出的算術提示（「… Now Ben has 」），答案為一位數。

| 模型 | 貪婪正確率 | 平均 $p$(正確) | 答案位置相對參考的 KL |
|---|---|---|---|
| 預訓練（階段 07） | 0.32 | 0.20 | 0 |
| REINFORCE，獎勵 $1[\text{ans} = a+b]$ | **0.82** | **0.80** | 1.37 |
| 在（正確、隨機錯誤）配對上做 DPO | 0.78 | 0.76 | — |

**解讀。** 以可驗證獎勵訓練 150 步，讓模型從模仿語料中 30% 錯誤的算術，變成五次有四次答對。以同一個檢查器構造的配對訓練的 DPO，不需抽樣就達到大部分的效果。兩者都沒有達到 100%：KL 錨定把策略拉在一個經常自信地答錯的參考附近，而一個以 1 187 個故事訓練的 3 層模型還沒有把加法學到可靠答對的程度——後訓練只能重新加權模型本來就能產生的東西（§9.5.3）。

## 詳解例題 9.7——一個字元的錯誤造成的獎勵駭取

**設定。** 與詳解例題 9.6 相同，但只要答案*至少*為 $a + b$，檢查器就回傳 1——本來要寫 `==`，卻寫成 `>=`。

| | 訓練獎勵（最後 20 步） | 訓練樣本的真實正確率 | 留出集貪婪正確率 | 平均 $p$(正確) |
|---|---|---|---|---|
| 有錯的檢查器 | **0.98** | 0.08 | **0.06** | 0.10 |

**解讀。** 回答「9」對任務中的每個提示都滿足「至少 $a+b$」（和從不超過 9）。策略在 150 步內就發現了這一點：它的獎勵近乎完美，而算術比後訓練之前還差（0.06 對 0.32）。由有錯檢查器算出的每一個監控數字都說這次訓練很成功。只有一個*獨立的*量測——留出提示上的真實正確率——揭露了真相。這就是通往單元 10 的橋。

## 詳解例題 9.8——解讀一個 KL

**設定。** 詳解例題 9.6 的 REINFORCE 執行結束時，答案位置的 $\mathrm{KL}(\pi\,\Vert\,\pi_{\text{ref}}) = 1.37$ nats。

**一個較低的參考點。** 從一個給正確數字 0.2 的參考分布出發，把 0.8 的機率移到正確數字上、其餘按比例保留，代價是 $0.8\ln\frac{0.8}{0.2} + 0.2\ln\frac{0.2}{0.8} = 0.832$ nats。

**解讀。** 量到的 1.37 更大：策略也重新塑造了剩餘機率在錯誤數字之間的分配方式。KL 是改變的總預算——它不說明*做了哪一種*改變，這就是為什麼有錯的執行（KL 1.32）和正確的執行（KL 1.37）在這個數字上看起來差不多。單元 11 問的是內部改變了什麼。
