這些實驗要把研究方法變成行為。不要一開始就執行現成指令。先寫下什麼結果會使你意外、哪些單位彼此獨立，以及每一種可能區間允許什麼決定。

程式：[`spine/stage12_capstone.py`](https://github.com/yhxuee/deep-learning-intelligent-systems/tree/main/spine) 與 `spine/test_spine.py` 的階段 12 測試。

## 每項實驗都要有實驗紀錄

每個實驗建立一個目錄，保留四份檔案：

```text
12-03-pairing/
  registration.json     # 在帶有結果資訊的執行前寫好
  runs.jsonl             # 每次嘗試各有一筆不可變紀錄
  analysis.py            # 把執行紀錄轉成表格與區間
  report.md              # 結果、偏離、解讀與下一項檢驗
```

登記應命名假說、估計目標、實驗單位、條件、主要指標、最小有意義效應、分析、決策規則、排除、停止規則、種子或抽樣規則，以及計算預算。記錄每一次嘗試，包括當機。可以保留探索圖，但不可暗中把它升格成登記的主要分析。

每份報告使用這個五行骨架：

1. **目標：**估計要指向哪個母體或程序。
2. **估計：**效應、區間、單位與獨立單位數。
3. **決定：**登記規則的輸出。
4. **稽核：**偏離、遺失執行、實作檢查與 AI 使用。
5. **邊界：**結果沒有確立什麼，以及下一項最能區分解釋的檢驗。

## 實驗 12.1——摘要值保護什麼、不保護什麼

**檢驗：**§12.3.11 與詳解例題 12.1。

**編輯前先預測：**在以下操作後，驗證會不會改變：（a）把 `0.02` 改成 `0.05`；（b）在 `record` 增加欄位；（c）調換物件鍵順序；（d）改變縮排；（e）同時改變紀錄與儲存的摘要值。

**步驟。**用 `preregister` 建立檔案。把印出的摘要複製到獨立、有時間戳記的位置；本練習可用一個在編輯前就記錄識別碼的 Git 提交。逐一單獨做每項變更並呼叫 `verify_preregistration`。

**預期結果結構。**摘要是由 `record` 的標準序列化計算。因此，調換鍵或改變檔案縮排會保留語意紀錄，不應改變摘要。改變值或加入欄位會改變語意紀錄；**只要可信摘要保持固定**，便能偵測。若紀錄與檔內摘要一起改，區域檢查會通過，這正好示範為何需要外部錨點。

**成果。**建立一張表，欄位為 `編輯`、`語意紀錄改變？`、`區域檢查通過？`、`外部錨點相符？`。最後完成一句話：「這個摘要可以證明 ___，前提是 ___；它不能證明 ___。」

## 實驗 12.2——計算區間以前先稽核實驗單位

**檢驗：**§§12.2.2–12.2.3。

**情境。**五個種子各有一個檢查點，每個都在 2,000 個驗證視窗上評估。很誘人的分析會把每個條件的 10,000 個視窗損失視為獨立。

**預測：**分別（a）只重抽視窗、（b）先對視窗平均再只重抽種子、（c）先抽種子再抽該種子內視窗時，區間如何改變。

**步驟。**保存每個種子與條件的逐視窗損失，計算三種區間，並明確畫出階層：

```text
訓練程序
└── 種子／獨立訓練執行
    └── 驗證視窗
```

**觀察重點。**只重抽視窗可能讓不確定性幾乎消失，卻忽略訓練執行之間的變異。只重抽種子回答總結專案的主要問題：新的訓練執行會如何。若兩層都來自目標母體，階層式重抽可以同時表示執行與評估項目的變異。

**反例。**若五個「種子」都載入同一個檢查點，它們就不是獨立執行。任何重抽語法都修不好重複的實驗單位。

**成果。**說明每個區間估計的是哪個估計目標。至少拒絕一個不匹配的區間，不要只說它「較寬」或「較窄」。

## 實驗 12.3——親眼看見微型先導有多不穩定

**檢驗：**§12.3.5 與詳解例題 12.4。

**預測：**由三對執行得到的配對差標準差 $s_d$，以及對 $delta=0.02$ nat/character 所隱含的樣本數。

**步驟。**在三個新種子上執行兩個條件，計算 $s_d$，再使用

$$
\hat n=\left\lceil
\left(\frac{2.8s_d}{0.02}\right)^2
\right\rceil
$$

換一組不重疊的三個種子重做。接著模擬：從已知常態分布抽取許多組三點樣本，每組計算 $\hat n$，並畫出分布。

**觀察重點。**所需樣本數取決於 $s_d^2$，所以微型變異估計的雜訊會被放大。三次執行的先導可以顯示 $n=5$ 很不合理，卻無法支持「恰好需要 173 對」的精確說法。$n=3$ 時，$s_d$ 的 bootstrap 區間本身也不穩定，不能當成保證。

**成果。**提出合理預算範圍，列出常態近似的假設，並指定一項不檢視處理效應的內部先導或盲化變異數重估規則。

## 實驗 12.4——修復並驗證配對設計

**檢驗：**§12.3.2 與詳解例題 12.3。

**問題。**在現有程式中，加入位置參數會在後續共享權重初始化前先消耗隨機數。因此，相同整數種子不會建立相同共享初始化。

**預測：**編輯程式前，先記下你預期修復後的跨條件相關、$s_d$ 與樣本數比率。

**步驟。**實作具名隨機流，使每個隨機張量都是 `(master_seed, parameter_name)` 的確定函數。最好先做實驗專用輔助函式；改變全域 `model.init_params` 可能改變所有先前主幹階段。若刻意修改全域輔助函式，必須執行完整迴歸測試。

在重跑消融以前先新增測試：

1. 兩個條件中同名共享參數逐位元相同；
2. 位置張量只存在於有位置的條件；
3. 改變主種子會改變共享張量；
4. 改變一個選用元件不會擾動無關隨機流；
5. 先前的梯度與訓練測試仍通過。

重新執行至少十對。報告 $\operatorname{corr}(Y_{1s},Y_{0s})$、$s_1$、$s_0$、$s_d$，以及

$$
\frac{n_{\text{paired}}}{n_{\text{uncorrelated}}}
\approx
\frac{s_1^2+s_0^2-2rs_1s_0}{s_1^2+s_0^2}
$$

**觀察重點。**正確共享初始化應改善設計，卻不保證結果高度正相關。訓練動力學可能放大微小條件差異。若 $r$ 仍接近零，檢查 dropout 或抽樣隨機流、批次順序、數值分歧，以及兩個結果是否本來就弱耦合。

**成果。**初始化測試證據加上修復前後變異表。不要只因平均往想要的方向移動，就宣稱修復「有效」。

## 實驗 12.5——設計負擔得起且資訊充分的消融

**檢驗：**§§12.3.3–12.3.6 與 §12.7.3。

**目標。**問一個現有預算真的能解析的問題。它不必是原設定下的原始 $0.02$ 門檻。

**步驟。**在帶有結果資訊的執行前：

1. 選擇最小有意義效應 $\tau$ 並說明理由；
2. 用修復配對後的先導變異規劃 $n$；
3. 說明問題是優效性（$\Delta>\tau$）、非劣性還是等效性（$|\Delta|<\tau$）；
4. 登記相應的區間規則——三者不能互換；
5. 登記失敗處理與最大預算；
6. 在結果目錄以外錨定登記；
7. 完全依照登記執行與分析。

若規劃預算負擔不起，應在看見新結果以前改問題：提高最小效應、改善量測、測試較便宜設定，或明確進行精確度先導。不要承諾一定有定論。

**觀察重點。**得到支持有限決策的窄區間，或誠實解釋為何仍無法定論。程式標籤 `"not needed"` 只表示區間在其單尾規則中低於正門檻；它本身不是以零為中心的等效性結論。

**成果。**登記、外部錨點、完整執行帳本、可執行分析，以及一段說明寬度、深度、資料、訓練長度、單位與不確定性的發現。

## 實驗 12.6——量測分岔小徑花園

**檢驗：**§12.2.7、§12.3.8 與詳解例題 12.5。

**預測：**列舉替代分析以前，先猜有多少種看似合理的分析會跨過慣例門檻，以及符號是否一致。

**步驟。**保持登記分析不變。在另一份探索筆記中，跨越下列選擇組成至少 16 種多重分析：

- 保留所有執行，或使用明確離群規則；
- 平均、中位數或截尾平均；
- 配對分析，或錯誤的非配對分析；
- 單尾或雙尾問題；
- bootstrap 或 $t$ 區間；
- 只看原始、只看重現，或事前指定的合併；
- NLL 或次要指標；
- 零或實務門檻。

呈現每條小徑，不只呈現有趣結果。有些組合可能無效；標示並解釋原因，不要刪除。

**觀察重點。**分析選擇如何改變符號、大小、區間或標題。多重分析描述敏感度，不會事後把所有小徑變成確認性。若 16 條小徑有三條跨過門檻，結論不是「三次獨立確認」。

**成果。**規格曲線或完整結果表，再寫兩段：能挑出的最強故事，以及登記允許的陳述。標出挑選故事中每個無法成立的句子。

## 實驗 12.7——針對明確共同錯誤做重現

**檢驗：**§§12.3.9 與 12.5.6。

從單元 01–11 選一個發現，命名它最可能共享的失敗模式，再沿該維度設計具獨立性的重現。

例子：

- 懷疑程式錯誤 → 不閱讀原函式，依數學描述重新實作；
- 懷疑資料洩漏 → 建立時間分離或來源分離的新評估集；
- 懷疑分析者偏差 → 在凍結分析檔以前隱藏條件標籤；
- 懷疑架構依賴 → 在真正不同的模型家族重做；
- 懷疑指標被鑽漏洞 → 增加具有獨立動機的結果指標。

開始前，說明直接再現與更強重現各自檢驗什麼。比較效應估計與區間，不把結果壓縮成「重現／未重現」。不一致可能揭露調節因子、實作差異或估計不精確。

**成果。**建立獨立性矩陣，把程式、資料、分析者、模型、指標與基礎設施標成 `共享`、`部分獨立` 或 `獨立`，並說明理由。

## 實驗 12.8——驗證優先的總結專案

**檢驗：**整本書。**成果：**可重現的報告套件與口試答辯。

1. **重現**單元 01–11 的一個量化結果，起初只使用書面描述。允許 AI 協助，但要記錄每一處歧義與額外查閱來源。
2. **稽核**實作與資料後才解讀分數。至少示範一項正控制與一項負控制。
3. **找出失敗模式**——使系統失效的輸入、分布偏移或設定——並對正確單位量化不確定性。
4. **提出競爭解釋**，選擇一項至少會讓兩種解釋做出不同預測的介入。
5. **登記並檢驗一項延伸**，包含估計目標、有意義效應門檻、合理預算、失敗規則與外部錨定程序。
6. **沿一個獨立維度重現**，刻意攻擊一項可能的共同錯誤。
7. **揭露 AI 使用**：提示或工作規格、生成差異、輸出、人工覆寫與驗證。包含一個被檢查抓到的錯誤；若沒有自然出現錯誤，植入已知故障並證明檢查抓得到。
8. **口頭答辯證據**：什麼只是結果、什麼支持有限發現、什麼仍屬探索，以及哪個後續觀察最可能改變你的信念。

### 總結專案驗收門檻

| 門檻 | 最低證據 |
|---|---|
| 來源鏈 | 程式、資料、環境與執行識別碼連到每張主要表格 |
| 實作 | 針對性測試，加正控制與負控制 |
| 統計 | 明確說明實驗單位、估計目標、效應、區間與遺失執行 |
| 登記 | 有時間戳記的外部錨點與可見偏離 |
| 重現 | 命名獨立維度與共享錯誤 |
| 主張 | 每句話都不超出已測系統與母體 |
| AI 協助 | 委託步驟及其驗證器可稽核 |

精美報告若無法通過實作或來源鏈門檻，就不及格。設計健全的虛無或無法定論結果可以及格。總結專案評估的是你能否建立自我修正的研究流程，而不是偏好的假說能否勝出。
