## 實驗 6.1——讓 FLOP 公式可以執行

**問題。** 實作是否恰好執行命題 6.1 所計數的矩陣乘積？

使用 $V=13$、$d=16$、$L=3$、$T=10$ 與 $B=4$。先在紙上算：

$$
N_{\text{mm}}=12Ld^2+Vd=9{,}424,
$$

$$
F_{\text{step}}=BT(6N_{\text{mm}}+12LTd)=2{,}492{,}160.
$$

接著重設 `model.FLOPS["count"]`，呼叫一次 `loss_and_grads`，把整數計數器與預測比較。只把 $T$ 改為 5、10、20，並記錄計數除以 $BT$ 的結果。

**控制。** 固定 $V,d,L,B$ 與所有架構開關。計數器只包含經過 `mm` 的呼叫；它不是硬體效能計數器。

**解讀。** 完全相等驗證一項實作不變量：宣告的矩陣乘積與推導吻合。這不表示 softmax、正規化、索引或 Python 不需要機器指令。把每詞元 FLOPs 對 $T$ 作圖，應得到截距 $6N_{\text{mm}}$、斜率 $12Ld$ 的直線。若不吻合，先檢查每個 `mm` 的形狀，再決定要改程式或公式。

## 實驗 6.2——從自己的機器畫出 roofline

**問題。** 在這台機器上，矩陣乘法於何種算術強度由頻寬敏感轉成計算敏感？

1. 建立 float32 矩陣，對 $n=16,32,\ldots,4096$ 的 `A @ B` 計時。每個大小先暖機，至少做五次計時，取中位數。
2. 以 $2n^3/t$ FLOP/s 計算達成速率。在「$A$、$B$ 各讀一次，$C$ 寫一次」的理想化流量下，強度是
   $$I_{\min}=\frac{2n^3}{3(4n^2)}=\frac{n}{6}\ \text{FLOPs/byte}.$$
3. 用大於末級快取的陣列估計大陣列複製頻寬。讀取與寫入的位元組都要計入，並報告這個慣例。
4. 把達成的 GFLOP/s 對 $I_{\min}$ 作圖。標出實測頻寬線 $P=\beta I$，以及大矩陣的觀察平台。
5. 對主幹模型的一個訓練步計時。以命題 6.1 的計數除以牆鐘時間，再除以**實測平台**而不是宣傳峰值，得到本機使用率。

**控制與陷阱。** 記錄 dtype、陣列布局、BLAS 程式庫與執行緒數。關閉其他重工作。小矩陣會受呼叫與直譯器額外負擔主導；複製可能由快取供應；熱降頻會讓後面的試驗變慢。$I_{\min}$ 是樂觀的流量模型，不是實測位元組。

**解讀。** 你可能看到上升區與平台，但筆電 CPU 沒有義務畫出乾淨的教科書 roofline。只要座標與單位能讓你解釋偏差，而不是刪掉偏差，實驗就成功了。

## 實驗 6.3——KV 快取省下什麼，又沒有省下什麼

**問題。** 重算完整前綴與快取鍵／值，會如何隨上下文位置縮放？

先執行 `python spine/stage05_kv_cache.py`。相信計時之前，先驗證 `spine/test_model.py` 已編碼的正確性控制：在每個位置，快取 logits 都在容許誤差內等於完整重算。

接著使用同一個隨機模型與固定批次，選擇不超過 `max_len` 的上下文長度，例如 8、16、32、64、120。每個長度都對兩條路徑暖機，至少執行十次並報告中位數。記錄：

- 以完整前綴重算下一個詞元的毫秒數；
- 一個快取解碼步的毫秒數；
- `cache.nbytes()` 的快取位元組，以及公式 $2BLtd\,b$ 的結果；主幹模型預設 float64 陣列，所以 $b=8$；
- 加速比，以及信賴區間或至少最小—最大範圍。

**預測。** 完整重算會重複先前所有權重乘積與注意力工作。快取解碼重用先前的 $K,V$，但新 query 仍要注意全部 $t$ 個快取位置；因此，快取時間可能隨 $t$ 成長。它應該長得比較慢，不是由數學保證維持平坦。

**失敗結果的解讀。** 在這個極小的 NumPy 尺度，串接、配置與直譯器額外負擔可能使快取反而更慢。這不否定算術節省；它表示省下的 FLOPs 不是所量測的瓶頸。精確 logits 控制與計時結果都要報告。

## 實驗 6.4——讓縮放定律先預測，再解釋

**問題。** 以五個較小寬度擬合的曲線，能否預測沒看過的第六個寬度？

執行：

```bash
python spine/stage06_scaling.py --seed 0
```

腳本以相同詞元預算訓練寬度 8、12、16、24、32，擬合 $L(N)=E+AN^{-\alpha}$，並在訓練寬度 48 **之前**，把該寬度的預測寫入 `checkpoints/stage06_prediction.json`。下一次執行會覆寫它，請先保存。

再以 `--seed 1`、`--seed 2` 重複；接著用 `--steps 1000` 對三個種子再做一輪。看過寬度 48 後重新擬合，不可再稱為預測。每種條件記錄預測 NLL、觀察 NLL、帶正負號的誤差、種子分散與擬合的 $(E,A,\alpha)$。

**控制。** 固定語料切分、分詞器、最佳化器排程、上下文長度與評估視窗。這裡的「相同步數」表示訓練詞元數相同，不表示 FLOPs 相同；較寬模型會消耗更多計算。

**解讀。** 檢查誤差是否與種子變異同量級，以及詞元預算減半是否改變擬合指數或下限。只有五個含雜訊的點時，即使內插看起來平滑，參數估計也可能不穩。一個預測失誤是這次擬合與區間的證據，不是所有縮放關係都不存在的證據。

## 實驗 6.5——配置固定計算預算

**問題。** 固定算術量下，應讓小模型看更多詞元，還是讓大模型看較少詞元？

選擇寬度 8、12、16、24、32、48，並固定 $L,T,B$。對每個寬度，計算每詞元矩陣乘積量

$$
c(d)=6N_{\text{mm}}(d)+12LTd,
$$

再配置 $D(d)=\lfloor C/c(d)\rfloor$ 個訓練詞元，換算成完整步數 $\lfloor D/(BT)\rfloor$。選一個讓每個模型都有足夠步數學習、整輪又負擔得起的 $C$；查看損失前先寫下 $C$。報告整數取整造成的未用餘額。

至少訓練三個種子，以誤差棒畫出保留資料 NLL 對寬度，並用實驗 6.4 獨立擬合的常數，把實證最小值與命題 6.2 比較。

**不要預先保證 U 形。** 玩具掃描可能單調或含雜訊，因為候選寬度錯過最佳點、可分離擬合定律不佳，或小模型受最佳化限制。結論必須有條件：「在這些寬度、此語料、排程與預算下……」。如果某個寬度只分到幾步，應放大 $C$，不可把未訓練模型解讀成縮放定律。

## 實驗 6.6——用重算購買記憶體

**問題。** 丟棄區塊內部狀態能省下多少激活值位元組，又要用多少額外時間購買這份節省？

另做一份實驗用訓練路徑。基準版保留 `backward` 所需的每個陣列；重算版只保留每個區塊的輸入與不可省的邊界狀態，丟掉內部注意力／MLP 陣列，並在該區塊反向傳遞前立刻重跑一次前向計算。

兩條路徑使用相同的 6 層參數與批次。計時前，先把損失與每個參數梯度和基準比較；報告最大絕對與相對誤差。接著：

1. 以一套有文件說明、避免重複計算的規則，加總所保留激活陣列的 `nbytes`；
2. 可另外量測程序峰值常駐記憶體，但要註明 Python 配置器可能保留已釋放緩衝區；
3. 暖機後交替重複兩種試驗，報告每步時間中位數；
4. 計數額外的 `mm` FLOPs，不要先假定時間比例。

**預測。** 保留的激活位元組應下降，FLOPs 與通常的牆鐘時間則上升。精確比例取決於保留哪些邊界，以及瓶頸是配置還是記憶體流量。若梯度有實質變化，你改變了計算，而不是實作檢查點。若明確保存的位元組下降但程序 RSS 沒變，要區分活張量與配置器保留的記憶體。

## 繳交內容

每個實驗都要交：預先登記的預測、完整指令與種子、原始表格、必要時的一張圖、正確性控制，以及包含至少一個替代解釋的五句解讀。目標不是六條漂亮曲線，而是六個可稽核的量測論證。
