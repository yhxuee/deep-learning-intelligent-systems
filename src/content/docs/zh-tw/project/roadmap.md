## 交付策略

**靜態優先。** 本書是部署在 GitHub Pages 上的 Astro Starlight 網站，由 Git 中的 Markdown 建置，從第一天起就有提示詞包與機器可讀的端點。託管式 AI 家教是另外、選用的服務，只有在評估顯示它比可攜式提示詞更能提升*獨立*學習時才會加入。本書必須在沒有帳號、沒有出版方出資的推論服務，以及只有 Markdown 原始檔的離線狀態下，仍然完全可用。

## 階段與門檻

| 階段 | 交付內容 | 門檻 | 狀態 |
|---|---|---|---|
| 0 · 編輯概念驗證 | 學習成果；12 單元結構；Atlas 格式；一個完整單元；評分規準；引用政策 | 讀者不靠 AI 完成範例單元 | ✅ |
| 1 · 靜態 MVP + 提示詞包 | 網站、搜尋、參考文獻、有型別的 Atlas、提示詞、單元 03–05 的實驗；llms.txt／atlas.json；MCP 伺服器 | 可重現的建置；自動檢查；行動裝置；無需帳號 | ✅ |
| 1.5 · 深度改寫 | 單元 03–05 改寫為完整的十部分章節；撰寫標準；先講解的 AI 導師政策；凍結 AI 代理工具的**功能開發**；互動圖表；繁體中文版 | 每個單元不靠 AI 服務也能教；每個詳解例題數字都由程式碼重現；通過學科與教學審查 | ⏳ **目前**——完整初稿已寫成，等待審查 |
| 2 · 內容擴充 | 其餘九個單元達到撰寫標準（每單元約 40–70 頁）；數學附錄；主幹專案階段 04–11；更多 Atlas 節點；試行回饋 | 實驗可重現；觀察到不使用 AI 的遷移成效 | ⏳ |
| 3 · 教學評估 | 比較傳統教學、核心教材 + 一般 AI、核心教材 + 結構化 AI 導師；延遲與遷移測驗；預先登記 | 獨立學習成效足以支持擴充；公開零結果 | ⏳ |
| 4 · 選用的託管式 AI 導師 | 無伺服器閘道、供應商抽象層、選擇加入的學習者狀態、預算上限、安全與教學測試 | 在可接受的成本、隱私與供應商風險下，比提示詞包有實質附加價值 | ⏳ |
| 5 · 社群與採用 | 貢獻模式、教師指南、評量套件、翻譯、語意化版本發布 | 獨立教師不需要專案基礎設施也能用它教學 | ⏳ |

## 功能凍結（自 v1.2 起）

在核心教材達到[撰寫標準](/zh-tw/project/writing-standard/)之前，不再開發 AI 代理工具、圖形視覺化、託管式家教或個人化管線。現有的基礎設施——網站、Atlas、MCP 伺服器、提示詞包、實驗、CI——已經足夠。心力放在正文上。互動圖表與繁體中文版屬於正文的一部分：它們直接服務於閱讀，而不是新的平台功能。

## MVP 明確不包含

託管的 GPU 訓練 · 學習管理系統整合 · 高風險的自動評分 · 自主研究代理 · 強制帳號 · 收集使用者對話 · 專有的提示詞執行環境 · 前端程式碼中的 API 金鑰。

## 評估議程

| 構念 | 量測方式 |
|---|---|
| 持久的理解 | 延遲進行、不靠協助的概念與推導測驗 |
| 遷移 | 所學範例之外的新機制或新任務 |
| 錯誤偵測 | 診斷植入的錯誤與有缺陷的 AI 解釋 |
| 科學推理 | 假設、對照與替代解釋的品質 |
| 人–AI 協作 | 標準化開放任務上的產出品質與成本 |
| 認知自主性 | 經過一段 AI 輔助學習之後的獨立表現 |
| 公平性 | 不同背景準備、硬體取得與語言之間的差異 |

樂觀與謹慎兩方面都有證據 [Kestin et al. 2025](/zh-tw/references/#kestin-2025)；[Bastani et al. 2025](/zh-tw/references/#bastani-2025)。這裡提出的學習順序應該被檢驗，而不是被假定為最佳。
