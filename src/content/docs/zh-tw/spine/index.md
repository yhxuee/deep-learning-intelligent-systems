抽象的問題需要一個具體的對象來發問。主幹專案（spine project）是**一個你在整個核心教材中建構、擴充並探究的小型語言模型**。史丹佛大學的 CS336 證明了從零打造語言模型可以成為一門課的主軸 [CS336](/zh-tw/references/#cs336-2026)；主幹專案把同樣的想法縮小到筆電規模，使用一份精神上類似 TinyStories 的簡單故事語料 [Eldan & Li 2023](/zh-tw/references/#eldan-2023)。

每個階段都有一個**驗證目標**——一個不依賴任何 AI、就能告訴你這個階段是否正確的數字或不變量。所有目標都在 CI 中執行（`spine/test_spine.py`、`spine/test_model.py`）。

## 一個模型、一份語料

- **`spine/model.py`** 是一個 NumPy 寫成的僅解碼器 Transformer（前置層正規化、綁定嵌入、學習的位置、KV 快取），其反向傳遞完全手寫——也就是單元 03 與 04 的推導被實際執行。每個梯度都與中央有限差分比對，而一個植入計數器的矩陣乘積會計算 FLOPs，讓單元 06 的 $6N + 12LTd$ 法則被驗證到最後一個運算。消融與修補注意力頭的介面供單元 11 使用。你可以用框架的自動微分寫自己的階段，再與這份參考實作比較。
- **`spine/data/tales.txt`** 由 `make_tales.py` 產生：1,400 個短篇故事、50 個不同字元，最後 140 個為保留資料。它是合成的，因此沒有授權問題，而且**植入了標準答案**：刻意植入 67 組重複配對、6 個洩漏到訓練資料中的保留故事、30% 錯誤的算術，以及只能靠複製才能預測的編造寵物名字，並把它們的位置寫進 `tales_manifest.json`。後面的階段必須偵測或處理每一項。

## 各階段

| 階段 | 單元 | 你加入的東西 | 驗證目標 |
|---|---|---|---|
| 01 | [01](/zh-tw/core/unit-01/) | 計數式二元語法、加 α 平滑 | 保留資料 NLL < $\ln V$；α → ∞ 恰好得到 $\ln V$ |
| 02 | [02](/zh-tw/core/unit-02/) | 綁定嵌入的分解式二元語法；神經 4 元語法 | 初始損失 $= \ln V$；查找梯度 = 獨熱梯度；可互換的符號合併；資料稀少時神經 4 元語法勝過計數 |
| 03 | [03](/zh-tw/core/unit-03/) | 以你推導的梯度訓練的神經二元語法 | 初始損失 $=\ln V$；從上方收斂到計數最佳值 |
| 04 | [04](/zh-tw/core/unit-04/) | 因果自注意力：Transformer 區塊 | 每個參數的梯度檢查；因果性；勝過二元語法 |
| 05 | [05](/zh-tw/core/unit-05/) | KV 快取解碼 | 快取 logits = 完整重算；快取位元組 = 公式 |
| 06 | [06](/zh-tw/core/unit-06/) | FLOP 計算；五種寬度；縮放擬合 | 計數 FLOPs 恰好 $= BT(6N + 12LTd)$；擬合能還原已知定律；在第六次訓練之前寫下預測 |
| 07 | [07](/zh-tw/core/unit-07/) | MinHash 去重、污染檢查、預訓練 | 找到每一組植入的重複與洩漏，且沒有移除其他東西 |
| 08 | [08](/zh-tw/core/unit-08/) | 抽樣器；二維流匹配 | 抽樣器在極限下彼此化約；精確高斯場把雜訊輸運到資料 |
| 09 | [09](/zh-tw/core/unit-09/) | 帶 KL 錨定的 REINFORCE；DPO；獎勵駭客稽核 | 估計量不偏；KL 正則化最佳解 = 傾斜的參考分布；DPO 梯度 = 有限差分 |
| 10 | [10](/zh-tw/core/unit-10/) | 評估工具組 | 校準與失準預測器的 ECE；95% 自助法涵蓋率；配對讓區間變窄 |
| 11 | [11](/zh-tw/core/unit-11/) | 尋找、檢驗並消融複製電路 | 手工建構的歸納電路被每種方法找到；消融與修補的不變量 |
| 12 | [12](/zh-tw/core/unit-12/) | 預先登記的消融與重現 | 確定性；可偵測竄改的預先登記；機械式的決策規則 |

## 執行

```bash
cd spine
python -m pytest                         # 所有驗證目標，筆電上幾分鐘
python stage01_bigram.py                 # 幾秒
python stage04_attention.py              # 幾分鐘；寫出 checkpoints/stage04.npz
python stage07_pretrain.py               # 約 15 分鐘；寫出 checkpoints/stage07.npz
python stage09_post_training.py          # 使用階段 07 的檢查點
```

每個階段都只需要 NumPy。階段 05 與 08–11 載入階段 07 的檢查點，它已提交進版本庫，所以不需重新訓練就能執行。要使用真實語料，對階段 01–04 傳入 `--data path/to/text.txt`。

## 設計規則

- **掙來的抽象。** 參考實作中的每個梯度都是你推導過的（單元 03–04）；一旦你能以它檢查框架，就歡迎使用框架。
- **每個階段只改一件事**，並在執行前寫下預測。
- **筆電優先。** 每個階段都能在筆電 CPU 上幾分鐘內跑完；不需要 GPU。
- **先有標準答案，再下結論。** 凡是階段要偵測某樣東西（重複、污染、電路），都先植入或手工建構標準答案，讓偵測器本身也受到檢驗。
