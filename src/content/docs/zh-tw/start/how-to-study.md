本書不假設「閱讀」就是從第一行移到最後一行，而且每一行第一次都立刻看懂。深度學習把機率、微積分、線性代數、程式設計、系統與實驗設計接在一起。感到困惑很正常；真正要學的是如何定位並修補困惑。

目標不是背下十二章，而是能夠：

1. 解釋為何需要一項建構；
2. 推導它的核心機制；
3. 實作並測試小型版本；
4. 預測它如何失效；
5. 判斷實驗究竟確立了什麼。

## 最初 90 分鐘

若你剛接觸這個領域，先做以下事情，不必先規劃完整課程：

1. 閱讀[單元 01 的問題](/zh-tw/core/unit-01/)到「先備知識」。先不要打開附錄。
2. 在紙上回答預測題。有假設的粗略答案，比沒有答案好。
3. 閱讀[第一原理](/zh-tw/core/unit-01/first-principles/)前四節，到均勻基線為止。用計算機算 $-\ln 0.5$、$-\ln 0.1$ 與 $\ln 50$。
4. 用自己的話寫：「一個 nat 是 ___；NLL 越低越好，因為 ___；需要留出資料，因為 ___。」
5. 若已取得儲存庫，再執行主幹階段 01。檢視實作以前，先把輸出與基線比較。
6. 最後寫下一個尚未解決的問題；下一次學習就從它開始。

第一次刻意只使用一枚硬幣、一個對數與一張計數表。你不需要先懂 Transformer 才能開始。

## 五個層次

| 層次 | 內容 | 用途 | 需要 AI 嗎？ |
|---|---|---|---|
| **核心教材** | 十二個十部分單元 | 主論證、推導、例題、實驗與習題 | 不需要 |
| **附錄** | 依學科重新整理的數學 | 即時修補與之後統整 | 不需要 |
| **Atlas** | 簡短的驗證工具組 | 不變量、參考機制與已知失敗模式 | 不需要 |
| **Mentor** | 有版本的提示與機器可讀端點 | 替代解釋、評論與練習變化 | 選用 |
| **實驗室** | 筆電規模程式、測試與主幹專案 | 建構、量測與除錯 | 不需要 |

精熟所需的一切都不依賴 AI 服務。核心教材負責解釋，附錄修補數學缺口，測試提供關於程式的獨立證據。AI 可以調整節奏並產生變化，但它不是真理來源，也不擁有結論。

## 一個單元有十部分，但可讀兩遍

每個核心單元依序是：**問題 → 第一原理 → 數學建構 → 詳解例題 → 一般理論 → 跨領域連結 → 限制與反例 → 近期發展 → 實驗 → 習題與延伸學習。**

### 第一遍：建立因果故事

完整閱讀問題與第一原理。把數學建構與詳解例題交錯閱讀：一節引入方程式後，先自己做相應例題，再看解答。接著讀限制部分的第一節與最後一節，並執行主幹階段。

第一遍結束時，應能完成四句話：

- 「舊方法失敗，是因為……」
- 「新建構改變了……」
- 「核心方程式表示……」
- 「它在……時仍會失效。」

此時不必已記住每個證明。

### 深入一遍：讓證據可答辯

重新推導顯示公式，閱讀進階小節，為重要主張打開原始證據，先寫預測再做實驗，並解遷移題。目標不再是認得答案，而是找出隱藏假設、構造反例，並說明哪項觀察會改變結論。

詳細依賴圖見[閱讀路徑](/zh-tw/pathways/reading-paths/)。

## 六個精熟階段

| 階段 | 你要做的事 | AI 規則 | 完成證據 |
|---|---|---|---|
| 1. **問題** | 面對陌生問題；寫預測與假設 | **不使用** | 答案出現前已有預測 |
| 2. **理論** | 閱讀、標示形狀與單位、重推關鍵步驟 | 可選 Tutor 模式 | 能解釋每一項並重建主推導 |
| 3. **建構** | 從零實作錨定機制 | 對正在訓練的思考**不使用** | 不變量與梯度測試通過 |
| 4. **挑戰** | 尋找反例並評論看似合理的解釋 | 可用 Critic 模式 | 至少實際示範一項失敗 |
| 5. **實驗** | 設計能區分解釋的檢驗；擴充主幹 | 可用 Collaborator 模式 | 保存預測、程序、所有執行與不確定性 |
| 6. **遷移與答辯** | 解相鄰未見問題並替主張答辯 | **不使用** | 獨立解答加明確主張邊界 |

這些階段不是道德排名。建構時關閉 AI，是因為建構本身就是正在學的能力；後續實驗可以使用 AI，因為自動化此時是研究能力的一部分。

## AI 協助規則

> 只有在你能陳述輸出約定，並驗證重大錯誤時，才委託執行。絕不委託當前階段正在訓練的思考。

使用四步程序：

1. **之前：**寫清楚想要什麼、哪些必須固定，以及哪些檢查決定成功。
2. **期間：**保存提示或工作規格、程式差異、工具輸出、失敗嘗試與人工覆寫。
3. **之後：**執行獨立檢查。「AI 說它檢查過」不是獨立證據。
4. **反思：**指出檢查抓到的一個錯誤，或它仍可能漏掉的一項重大錯誤。

| 當前目標 | 合適用法 | 不合適捷徑 |
|---|---|---|
| 學連鎖律 | 自己推導一例後，請 AI 給第二個數值例 | 把 AI 推導抄成自己的重建 |
| 實作自動微分 | 不變量失敗後請它解釋錯誤 | 尚未理解累加就請它寫完整引擎 |
| 做規模研究 | 依凍結規格產生掃描管線與圖 | 讓代理挑選並只報告好看的執行 |
| 文獻查核 | 尋找候選一手來源 | 不打開來源就引用生成摘要 |
| 完成總結專案 | 自動化登記執行與成品收集 | 讓提案者、評估者與報告者藏在同一迴圈 |

## 卡住時怎麼辦

「我看不懂這一頁」太寬，無法修補。使用最小可行步驟：

1. **命名物件。**它是純量、向量、矩陣、分布、隨機變數、損失還是演算法？
2. **寫形狀與單位。**許多表面上的概念問題，其實是遺漏維度或未說明單位。
3. **代入小數字。**使用兩類、$2\times2$ 矩陣、一個注意力頭或兩狀態馬可夫鏈。
4. **分開定義與推論。**標出哪一項是定義、哪一項是假設、哪一項是推導。
5. **找第一個斷點。**重寫推導到最後一行能說明理由的位置，只問下一個轉換。
6. **即時使用附錄。**讀引用小節的開場與第一個例題，再回來。
7. **要求替代解釋。**要求保留相同符號、假設與目標方程式。
8. **檢驗解釋。**構造邊界案例或執行不變量；流暢不等於驗證。

若卡住超過一次學習，在後文不依賴它時，可以標記缺口後繼續。保留「理解債務」清單並安排修補；不要讓困惑默默變成假定知識。

## 每週證據紀錄

追蹤能力，不追蹤看過幾頁。每單元一筆短紀錄即可：

```text
問題：
預測與信心：
我能重建的推導：
已通過的實作檢查：
找到的反例：
實驗與不確定性：
AI 用於／如何驗證：
一件我仍無法答辯的事：
下次提取日期：
```

一週後不看答案，重做「推導」與「反例」。延遲重建比當天熟悉更能證明學會。

## 從哪裡開始

- **機率或微積分新手：**仍從單元 01 開始。只在引用時使用附錄 C、D、E；進入單元 02–03 前再學附錄 A、B。
- **程式新手：**先以普通陣列與迴圈完成階段 01，需要時學 NumPy 索引；不用等到學完一個框架才開始概念課。
- **已訓練過模型：**嘗試單元 01–03 的 AI-off 檢核點。只有在能推導與除錯時才跳過，不能只因術語眼熟。
- **主要關心評估：**使用[閱讀路徑](/zh-tw/pathways/reading-paths/)的評估優先路線，但不要略過最低限度的最佳化與注意力先備知識。
- **教師：**使用[評量](/zh-tw/assessment/)與[大學部路徑](/zh-tw/pathways/undergraduate/)，並分開回報獨立精熟與 AI 增強專案品質。

本書中的進度，是你能獨立檢查的主張、推導與實作集合正在增長，而不是你看過的頁數。
