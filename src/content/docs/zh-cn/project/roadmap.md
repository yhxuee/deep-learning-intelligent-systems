## 交付策略

**静态优先。** 本书是部署在 GitHub Pages 上的 Astro Starlight 网站，由 Git 中的 Markdown 构建，从第一天起就有提示词包与机器可读的端点。托管式 AI 家教是另外、选用的服务，只有在评估显示它比可携式提示词更能提升*独立*学习时才会加入。本书必须在没有账号、没有出版方出资的推理服务，以及只有 Markdown 源文件的离线状态下，仍然完全可用。

## 功能冻结（自 v1.2 起）

在核心教材达到[写作规范](/zh-cn/project/writing-standard/)之前，不再开发 AI 智能体工具、图形可视化、托管式家教或个性化流水线。现有的基础设施——网站、Atlas、MCP 服务器、提示词包、实验、CI——已经足够。心力放在正文上。交互式图表与繁体中文版属于正文的一部分：它们直接服务于阅读，而不是新的平台功能。

## MVP 明确不包含

托管的 GPU 训练 · 学习管理系统整合 · 高风险的自动评分 · 自主研究智能体 · 强制账号 · 收集用户对话 · 专有的提示词执行环境 · 前端代码中的 API 密钥。

## 评估议程

| 构念 | 度量方式 |
|---|---|
| 持久的理解 | 延迟进行、不靠协助的概念与推导测验 |
| 迁移 | 所学范例之外的新机制或新任务 |
| 错误检测 | 诊断植入的错误与有缺陷的 AI 解释 |
| 科学推理 | 假设、对照与替代解释的质量 |
| 人–AI 协作 | 标准化开放任务上的产出质量与成本 |
| 认知自主性 | 经过一段 AI 辅助学习之后的独立表现 |
| 公平性 | 不同背景准备、硬件取得与语言之间的差异 |

乐观与谨慎两方面都有证据 [Kestin et al. 2025](/zh-cn/references/#kestin-2025)；[Bastani et al. 2025](/zh-cn/references/#bastani-2025)。这里提出的学习顺序应该被检验，而不是被假定为最优。
