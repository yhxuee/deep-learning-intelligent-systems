这些实验要把研究方法变成行为。不要一开始就执行现成指令。先写下什么结果会使你意外、哪些单位彼此独立，以及每一种可能区间允许什么决定。

程序：[`spine/stage12_capstone.py`](https://github.com/yhxuee/deep-learning-intelligent-systems/tree/main/spine) 与 `spine/test_spine.py` 的阶段 12 测试。

## 每项实验都要有实验记录

每个实验建立一个目录，保留四份文件：

```text
12-03-pairing/
  registration.json     # 在带有结果信息的执行前写好
  runs.jsonl             # 每次尝试各有一笔不可变记录
  analysis.py            # 把执行记录转成表格与区间
  report.md              # 结果、偏离、解读与下一项检验
```

注册应命名假说、估计目标、实验单位、条件、主要指标、最小有意义效应、分析、决策规则、排除、停止规则、种子或采样规则，以及计算预算。记录每一次尝试，包括当机。可以保留探索图，但不可暗中把它升格成注册的主要分析。

每份报告使用这个五行骨架：

1. **目标：**估计要指向哪个总体或程序。
2. **估计：**效应、区间、单位与独立单位数。
3. **决定：**注册规则的输出。
4. **稽核：**偏离、遗失执行、实现检查与 AI 使用。
5. **边界：**结果没有确立什么，以及下一项最能区分解释的检验。

## 实验 12.1——摘要值保护什么、不保护什么

**检验：**§12.3.11 与例题 12.1。

**编辑前先预测：**在以下操作后，验证会不会改变：（a）把 `0.02` 改成 `0.05`；（b）在 `record` 增加字段；（c）调换对象键顺序；（d）改变缩排；（e）同时改变记录与存储的摘要值。

**步骤。**用 `preregister` 建立文件。把印出的摘要复制到独立、有时间戳记的位置；本练习可用一个在编辑前就记录识别码的 Git 提交。逐一单独做每项变更并调用 `verify_preregistration`。

**预期结果结构。**摘要是由 `record` 的标准序列化计算。因此，调换键或改变文件缩排会保留语义记录，不应改变摘要。改变值或加入字段会改变语义记录；**只要可信摘要保持固定**，便能检测。若记录与档内摘要一起改，区域检查会通过，这正好示范为何需要外部锚点。

**成果。**建立一张表，字段为 `編輯`、`語意紀錄改變？`、`區域檢查通過？`、`外部錨點相符？`。最后完成一句话：“这个摘要可以证明 ___，前提是 ___；它不能证明 ___。”

## 实验 12.2——计算区间以前先稽核实验单位

**检验：**§§12.2.2–12.2.3。

**情境。**五个种子各有一个检查点，每个都在 2,000 个验证窗口上评估。很诱人的分析会把每个条件的 10,000 个窗口损失视为独立。

**预测：**分别（a）只重采样窗口、（b）先对窗口平均再只重采样种子、（c）先抽种子再抽该种子内窗口时，区间如何改变。

**步骤。**保存每个种子与条件的逐窗口损失，计算三种区间，并明确画出阶层：

```text
训练程序
└── 种子／独立训练执行
    └── 验证窗口
```

**观察重点。**只重采样窗口可能让不确定性几乎消失，却忽略训练执行之间的差异。只重采样种子回答综合项目的主要问题：新的训练执行会如何。若两层都来自目标总体，阶层式重采样可以同时表示执行与评估项目的差异。

**反例。**若五个“种子”都加载同一个检查点，它们就不是独立执行。任何重采样语法都修不好重复的实验单位。

**成果。**说明每个区间估计的是哪个估计目标。至少拒绝一个不匹配的区间，不要只说它“较宽”或“较窄”。

## 实验 12.3——亲眼看见微型先导有多不稳定

**检验：**§12.3.5 与例题 12.4。

**预测：**由三对执行得到的配对差标准差 $s_d$，以及对 $delta=0.02$ nat/character 所隐含的样本量。

**步骤。**在三个新种子上执行两个条件，计算 $s_d$，再使用

$$
\hat n=\left\lceil
\left(\frac{2.8s_d}{0.02}\right)^2
\right\rceil
$$

换一组不重叠的三个种子重做。接着模拟：从已知正态分布抽取许多组三点样本，每组计算 $\hat n$，并画出分布。

**观察重点。**所需样本量取决于 $s_d^2$，所以微型差异估计的噪声会被放大。三次执行的先导可以显示 $n=5$ 很不合理，却无法支持“恰好需要 173 对”的精确说法。$n=3$ 时，$s_d$ 的 bootstrap 区间本身也不稳定，不能当成保证。

**成果。**提出合理预算范围，列出正态近似的假设，并指定一项不查看处理效应的内部先导或盲化方差重估规则。

## 实验 12.4——修复并验证配对设计

**检验：**§12.3.2 与例题 12.3。

**问题。**在现有程序中，加入位置参数会在后续共享权重初始化前先消耗随机数。因此，相同整数种子不会建立相同共享初始化。

**预测：**编辑程序前，先记下你预期修复后的跨条件相关、$s_d$ 与样本量比率。

**步骤。**实现具名随机流，使每个随机张量都是 `(master_seed, parameter_name)` 的确定函数。最好先做实验专用辅助函数；改变全局 `model.init_params` 可能改变所有先前主干阶段。若刻意修改全局辅助函数，必须执行完整回归测试。

在重跑消融以前先新增测试：

1. 两个条件中同名共享参数逐比特相同；
2. 位置张量只存在于有位置的条件；
3. 改变主种子会改变共享张量；
4. 改变一个选用组件不会扰动无关随机流；
5. 先前的梯度与训练测试仍通过。

重新执行至少十对。报告 $\operatorname{corr}(Y_{1s},Y_{0s})$、$s_1$、$s_0$、$s_d$，以及

$$
\frac{n_{\text{paired}}}{n_{\text{uncorrelated}}}
\approx
\frac{s_1^2+s_0^2-2rs_1s_0}{s_1^2+s_0^2}
$$

**观察重点。**正确共享初始化应改善设计，却不保证结果高度正相关。训练动力学可能放大微小条件差异。若 $r$ 仍接近零，检查 dropout 或采样随机流、批量顺序、数值分歧，以及两个结果是否本来就弱耦合。

**成果。**初始化测试证据加上修复前后差异表。不要只因平均往想要的方向移动，就宣称修复“有效”。

## 实验 12.5——设计负担得起且信息充分的消融

**检验：**§§12.3.3–12.3.6 与 §12.7.3。

**目标。**问一个现有预算真的能解析的问题。它不必是原设定下的原始 $0.02$ 阈值。

**步骤。**在带有结果信息的执行前：

1. 选择最小有意义效应 $\tau$ 并说明理由；
2. 用修复配对后的先导差异规划 $n$；
3. 说明问题是优效性（$\Delta>\tau$）、非劣性还是等效性（$|\Delta|<\tau$）；
4. 注册相应的区间规则——三者不能互换；
5. 注册失败处理与最大预算；
6. 在结果目录以外锚定注册；
7. 完全依照注册执行与分析。

若规划预算负担不起，应在看见新结果以前改问题：提高最小效应、改善度量、测试较便宜设定，或明确进行精确度先导。不要承诺一定有定论。

**观察重点。**得到支持有限决策的窄区间，或诚实解释为何仍无法定论。程序标签 `"not needed"` 只表示区间在其单尾规则中低于正阈值；它本身不是以零为中心的等效性结论。

**成果。**注册、外部锚点、完整执行帐本、可执行分析，以及一段说明宽度、深度、数据、训练长度、单位与不确定性的发现。

## 实验 12.6——度量分岔小径花园

**检验：**§12.2.7、§12.3.8 与例题 12.5。

**预测：**枚举替代分析以前，先猜有多少种看似合理的分析会跨过惯例阈值，以及符号是否一致。

**步骤。**保持注册分析不变。在另一份探索笔记中，跨越下列选择组成至少 16 种多重分析：

- 保留所有执行，或使用明确离群规则；
- 平均、中位数或截尾平均；
- 配对分析，或错误的非配对分析；
- 单尾或双尾问题；
- bootstrap 或 $t$ 区间；
- 只看原始、只看复现，或事前指定的合并；
- NLL 或次要指标；
- 零或实践阈值。

呈现每条小径，不只呈现有趣结果。有些组合可能无效；标记并解释原因，不要删除。

**观察重点。**分析选择如何改变符号、大小、区间或标题。多重分析描述敏感度，不会事后把所有小径变成确认性。若 16 条小径有三条跨过阈值，结论不是“三次独立确认”。

**成果。**规格曲线或完整结果表，再写两段：能挑出的最强故事，以及注册允许的陈述。标出挑选故事中每个无法成立的句子。

## 实验 12.7——针对明确共同错误做复现

**检验：**§§12.3.9 与 12.5.6。

从单元 01–11 选一个发现，命名它最可能共享的失败模式，再沿该维度设计具独立性的复现。

例子：

- 怀疑程序错误 → 不阅读原函数，依数学描述重新实现；
- 怀疑数据泄漏 → 建立时间分离或来源分离的新评估集；
- 怀疑分析者偏差 → 在冻结分析档以前隐藏条件标签；
- 怀疑架构依赖 → 在真正不同的模型家族重做；
- 怀疑指标被钻漏洞 → 增加具有独立动机的结果指标。

开始前，说明直接再现与更强复现各自检验什么。比较效应估计与区间，不把结果压缩成“复现／未复现”。不一致可能揭露调节因子、实现差异或估计不精确。

**成果。**建立独立性矩阵，把程序、数据、分析者、模型、指标与基础设施标成 `共享`、`部分獨立` 或 `獨立`，并说明理由。

## 实验 12.8——验证优先的综合项目

**检验：**整本书。**成果：**可复现的报告套件与答辩。

1. **复现**单元 01–11 的一个量化结果，起初只使用书面描述。允许 AI 协助，但要记录每一处歧义与额外查阅来源。
2. **稽核**实现与数据后才解读分数。至少示范一项正控制与一项负控制。
3. **找出失败模式**——使系统失效的输入、分布偏移或设定——并对正确单位量化不确定性。
4. **提出竞争解释**，选择一项至少会让两种解释做出不同预测的干预。
5. **注册并检验一项延伸**，包含估计目标、有意义效应阈值、合理预算、失败规则与外部锚定程序。
6. **沿一个独立维度复现**，刻意攻击一项可能的共同错误。
7. **揭露 AI 使用**：提示或工作规格、生成差异、输出、人工覆写与验证。包含一个被检查抓到的错误；若没有自然出现错误，植入已知故障并证明检查抓得到。
8. **口头答辩证据**：什么只是结果、什么支持有限发现、什么仍属探索，以及哪个后续观察最可能改变你的信念。

### 综合项目验收阈值

| 阈值 | 最低证据 |
|---|---|
| 来源链 | 程序、数据、环境与执行识别码连到每张主要表格 |
| 实现 | 针对性测试，加正控制与负控制 |
| 统计 | 明确说明实验单位、估计目标、效应、区间与遗失执行 |
| 注册 | 有时间戳记的外部锚点与可见偏离 |
| 复现 | 命名独立维度与共享错误 |
| 主张 | 每句话都不超出已测系统与总体 |
| AI 协助 | 委托步骤及其验证器可稽核 |

精美报告若无法通过实现或来源链阈值，就不及格。设计健全的虚无或无法定论结果可以及格。综合项目评估的是你能否建立自我修正的研究流程，而不是偏好的假说能否胜出。
