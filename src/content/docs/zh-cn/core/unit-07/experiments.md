实验不是“执行程序，看看会发生什么”。执行前要先写下处置、对照、指标，以及两种结果各自如何解释。下面的表格是一份精简预注册表。

| 字段 | 执行前要回答的问题 |
|---|---|
| 假设 | 你预期哪个方向或数值？理由是什么？ |
| 实验单位 | 文档对、留出故事、种子，还是整次训练？ |
| 处置与对照 | 只有哪一项决策改变？ |
| 固定预算 | 词元、更新次数、模型、优化器与评估是否固定？ |
| 主要指标 | 哪一个数字直接回答问题？ |
| 不确定性 | 二项区间、配对故事自助法、种子间差异，还是三者都要？ |
| 失败含义 | 预测失败时，先检查哪项假设？ |

标准文件是 [`spine/stage07_pretrain.py`](https://github.com/yhxuee/deep-learning-intelligent-systems/tree/main/spine)、`spine/data/make_tales.py` 与 `spine/data/tales_manifest.json`。进行干预实验时，把生成语料与检查点写入暂存目录；不要默默取代标准语料，或后续单元使用的阶段 07 检查点。

## 实验 7.1——用植入的标准答案稽核检测器

**问题。** 在哪些语料种子下，阶段 07 检测器能找回植入的精确副本、近似副本与保留集副本，同时不把未植入配对误标出来？

**预测。** 精确哈希应找回所有归一化后的精确副本。植入的保留集副本，其方向性 8-gram 覆盖率应为 $1$。MinHash 的近似重复召回率应很高，却不必恰为 $1$，因为分带具有随机性，一字编辑也会产生一段范围的 Jaccard 值。

**实验单位。** 召回率以一组植入配对为单位；误报检查则以一组未植入候选配对为单位。

**步骤。** 对种子 $2027,2028,2029,2030$：

1. 在内存或暂存目录中调用 `make_tales.build(seed)`；
2. 保留该种子传回的 manifest 作为标准答案；
3. 依 `held_out_start` 切分，只在训练集执行精确与近似去重，再做方向性污染评分；
4. 把检测配对与训练副本索引和 manifest 比较；
5. 对每一个额外标记，先查看精确 Jaccard 与原文，再称为误报——模板生成可能意外产生未植入但真正相似的副本。

**记录。** 分开记录精确副本召回率、近似副本候选召回率、应用 $J\ge0.7$ 后的最终近似召回率、$C_8\ge0.8$ 的污染召回率、额外标记数，以及最大的干净保留分数。除了比例也要报数量；“6/6”比“100%”更有信息。

**失败解释。** 漏掉精确副本代表实现或归一化错误。漏掉近似副本可能发生在最终阈值前（没有 LSH 碰撞）或阈值后（真实 Jaccard 小于 $0.7$），要把两者分开。额外污染标记可能是检测器误报，也可能是生成器的意外碰撞；只看 manifest 无法判断后者，必须查看原文。

## 实验 7.2——度量 LSH 的 S 形曲线

**问题。** 实际候选概率是否吻合

$$
P_{\text{cand}}(J)=1-(1-J^r)^b?
$$

**预测。** 若哈希行彼此独立随机，观察比例应在二项抽样误差内吻合公式。总行数同为 64 时，$(b,r)=(32,2)$ 应比 $(16,4)$ 提出更多低相似度配对。

**步骤。** 选择至少含 1,000 个符号的全集。对每个目标 $J\in\{0.1,0.2,\ldots,0.9\}$，建立 2,000 组交集与并集大小已知的集合对，并记录其**实际** Jaccard 值；整数集合大小未必能精确实现指定小数。产生独立 MinHash 排列，或清楚记录使用的有种子近似。测试 $(16,4)$ 与 $(32,2)$，但总行数都维持 64。

每个点都要画出：

- 理论候选概率；
- 实际候选比例；
- 95% 二项区间，例如 Wilson 区间。

**合理性计算。** 在 $J=0.7$ 时，$(16,4)$ 预测

$$
1-(1-0.7^4)^{16}\approx0.988.
$$

若有 2,000 组独立配对，二项标准误约为

$$
\sqrt{0.988(1-0.988)/2000}\approx0.0024.
$$

**失败解释。** 系统性不吻合可能表示各行相关、签章切分错误，或混淆了“同一个 band”与“同一行”。同时检验许多点时，单一点落在名目 95% 区间外并非不可能；要查看整条曲线，而不是由一个点声明失败。

## 实验 7.3——隔离训练集去重的效果

**问题。** 在固定计算量下，移除训练副本如何改变干净保留集 NLL？

**预测。** 符号不保证固定。去重会移除意外的过度加权，也让固定词元预算看见更多唯一范例；但重复也可能帮助模型学会常见模板。只有在检查副本类别内容之后，才能预注册有方向的预测。

**处置。** 去重后的训练故事。**对照。** 原始训练故事。两边都必须保持同一保留切分，并移除污染保留集的训练副本；否则实验会把去重与评估泄漏混在一起。

**控制。** 使用相同架构、初始参数种子、优化器、更新次数、批量大小、上下文长度、词表与评估故事。至少执行三个配对训练种子。“相同 epoch 数”不是固定计算量控制，因为数据集大小不同；应固定采样词元量或更新次数。

**主要指标。** 对种子 $s$ 与留出故事 $i$，记录每字符 NLL：$L^{\text{raw}}_{s,i}$ 与 $L^{\text{dedup}}_{s,i}$。把改善定义为

$$
\Delta_{s,i}=L^{\text{raw}}_{s,i}-L^{\text{dedup}}_{s,i},
$$

所以正值支持去重。报告平均值、配对故事层级分布与种子间差异。对故事做自助法估计的是题目不确定性；三个种子不足以精确描述训练执行不确定性，因此要明行三个种子的估计值。

**失败解释。** 区间包含零，表示此实验以目前统计功效无法判定符号，不代表两套程序完全相同。若看到很大增益，必须先确认词表、去污染、更新次数与检查点击择都相同，才能称为因果结果。它也不能直接与例题 7.8 中同时改变多项因素的阶段 04—07 差异相比。

## 实验 7.4——植入并度量记忆

**问题。** 在固定训练计算量下，重复是否提高序列专属似然与精确复现？

**设计。** 训练前，依与模型结果无关的规则选出六篇留出故事与六篇配对对照故事。建立暂存训练集，把每篇指定故事插入 $m\in\{0,1,5,20\}$ 次。这些是刻意污染的实验数据；绝对不能把它们的分数当成诚实的模型评估。

以相同词元／更新预算训练配对种子。对故事 $i$ 度量：

1. 完整故事 NLL；
2. 给定固定 40 字符前缀后的后缀 NLL；
3. 贪心续写与原文相同的最长前缀；
4. 在数个预注册前缀长度与采样种子下的精确复现率。

一个有用的对比是差中差。令 $P$ 表示植入故事、$C$ 表示配对对照、$m$ 表示副本数、$0$ 表示干净执行：

$$
\Delta_m=
[(L_{P,m}-L_{P,0})-(L_{C,m}-L_{C,0})].
$$

植入故事的 NLL 下降时，$\Delta_m$ 为负。查看结果前就要先声明这个符号约定。

**预测。** 更多副本通常应降低植入故事的 NLL，并增加精确续写。但每个种子的反应不必单调：优化噪声、被排挤的其他训练范例，以及共同模板，都可能模糊只有六个题目的估计。

**失败解释。** 没有贪心精确吻合，不代表没有记忆；NLL 仍可能改变。插入一次后出现精确吻合，也不能建立普遍的一次学习定律；故事可能高度模板化，即使没有副本也可预测。必须和配对对照及 $m=0$ 模型比较。

## 实验 7.5——不偷换问题地比较自回归与遮罩目标

**问题。** 在配对计算量下，目标如何改变下一字符预测与冻结表示质量？

**模型。** 在形状允许处使用相同宽度、深度与参数初始化。自回归模型采因果注意力，在几乎所有位移位置都有损失；遮罩模型采双向注意力，选取 15% 位置并预测原字符。除了优化更新次数，也要报告目标预测总数；相同步数不代表相同监督目标数。

**评估。** 使用三栏，而不是声明一个含义不明的赢家：

1. **原生验证损失：**AR 下一字符 NLL 与遮罩重建 NLL，并清楚标记两者单位不可直接比较；
2. **共同末字测试：**隐藏最后一个字符、不提供右侧上下文，让两个模型都评分；
3. **冻结探针：**以相同数量训练范例拟合相同正则化探针，再在未见故事模板上测试“是否含算术”与“写出的答案是否正确”。

探针正则化要用探针验证切分选择，不能偷看最终保留集。报告类别平衡、准确率与机会／多数类别基线。“是否含算术”可能只靠浅层词汇线索就能解，因此更难的正确性探针是伴随检查，而不是推理能力证明。

**预测。** AR 直接针对共同末字接口训练，所以具有目标对齐优势。遮罩模型在预训练时可看两侧，可能有利于某些全故事探针。在这个小规模下，两种结果都不保证。

**失败解释。** 探针差异可能来自目标、注意力遮罩、目标损失数量或优化，而不只是目标本身。这个实验比较的是两套完整训练配方。若要更严格的因果主张，还要加入每次只改一个组件的消融。

## 实验 7.6——复现标准阶段 07 产物

**问题。** 目前签入的流水线，是否仍能复现数据清理不变量与已存储检查点的指标？

从仓库根目录先执行不覆写产物的验证：

```bash
.venv/bin/python -m pytest spine/test_spine.py -k stage07 -q
.venv/bin/python spine/stage07_pretrain.py --steps 4000 --no-save
```

`--no-save` 可避免探索性执行取代 `spine/checkpoints/stage07.npz`。已签入检查点的诠释数据记录 4,000 次更新，以及每字符约 $0.242$ nat 的保留 NLL。只有当程序、数据、数值库与种子相同，附近数值才能作为复现目标；同时要记录精确 commit 与环境。

**必要证据。** 保存：

- 清理前后的副本与污染数；
- 清理后保留集重叠的最大值与中位数；
- 完整训练损失日志，而不只是最后一行；
- 最终保留 NLL 与实际耗时；
- 命令、commit 哈希与软件版本。

**验收条件。** 测试必须为标准 manifest 找回所有植入项目；清理后每个保留污染分数都低于 $0.8$；训练过程不得出现非有限值。近似 NLL 目标检查的是可复现性，不是数学不变量，也不是每项能力都进步的证据。

只有在产物通过验收之后，它才应成为单元 08–12 采样、后训练、评估与拆解的检查点。这个顺序能让后续结论绑定到同一个可稽核模型，而不是碰巧最近执行的那一个。

## 实验报告模板

每个实验都依下列顺序报告：

1. 预注册预测与符号约定；
2. 处置、对照与所有固定项；
3. 原始计数或逐项数值；
4. 带不确定性的汇总；
5. 标明种子与单位的图；
6. 哪种结果原本会改变你的结论；
7. 本实验**没有**建立的一项主张。

最后一行是结果的一部分，不是事后补上的免责声明。
