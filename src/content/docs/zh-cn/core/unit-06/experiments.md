## 实验 6.1——让 FLOP 公式可以执行

**问题。** 实现是否恰好执行命题 6.1 所计数的矩阵乘积？

使用 $V=13$、$d=16$、$L=3$、$T=10$ 与 $B=4$。先在纸上算：

$$
N_{\text{mm}}=12Ld^2+Vd=9{,}424,
$$

$$
F_{\text{step}}=BT(6N_{\text{mm}}+12LTd)=2{,}492{,}160.
$$

接着重设 `model.FLOPS["count"]`，调用一次 `loss_and_grads`，把整数计数器与预测比较。只把 $T$ 改为 5、10、20，并记录计数除以 $BT$ 的结果。

**控制。** 固定 $V,d,L,B$ 与所有架构开关。计数器只包含经过 `mm` 的调用；它不是硬件性能计数器。

**解读。** 完全相等验证一项实现不变量：声明的矩阵乘积与推导吻合。这不表示 softmax、归一化、索引或 Python 不需要机器指令。把每词元 FLOPs 对 $T$ 作图，应得到截距 $6N_{\text{mm}}$、斜率 $12Ld$ 的直线。若不吻合，先检查每个 `mm` 的形状，再决定要改程序或公式。

## 实验 6.2——从自己的机器画出 roofline

**问题。** 在这台机器上，矩阵乘法于何种算术强度由带宽敏感转成计算敏感？

1. 建立 float32 矩阵，对 $n=16,32,\ldots,4096$ 的 `A @ B` 计时。每个大小先暖机，至少做五次计时，取中位数。
2. 以 $2n^3/t$ FLOP/s 计算达成速率。在“$A$、$B$ 各读一次，$C$ 写一次”的理想化流量下，强度是
   $$I_{\min}=\frac{2n^3}{3(4n^2)}=\frac{n}{6}\ \text{FLOPs/byte}.$$
3. 用大于末级缓存的数组估计大数组复制带宽。读取与写入的字节都要计入，并报告这个惯例。
4. 把达成的 GFLOP/s 对 $I_{\min}$ 作图。标出实测带宽线 $P=\beta I$，以及大矩阵的观察平台。
5. 对主干模型的一个训练步计时。以命题 6.1 的计数除以墙钟时间，再除以**实测平台**而不是宣传峰值，得到本地使用率。

**控制与陷阱。** 记录 dtype、数组布局、BLAS 库与线程数。关闭其他重工作。小矩阵会受调用与解释器额外负担主导；复制可能由缓存供应；热降频会让后面的试验变慢。$I_{\min}$ 是乐观的流量模型，不是实测字节。

**解读。** 你可能看到上升区与平台，但笔记本电脑 CPU 没有义务画出干净的教科书 roofline。只要坐标与单位能让你解释偏差，而不是删掉偏差，实验就成功了。

## 实验 6.3——KV 缓存省下什么，又没有省下什么

**问题。** 重算完整前缀与缓存键／值，会如何随上下文位置缩放？

先执行 `python spine/stage05_kv_cache.py`。相信计时之前，先验证 `spine/test_model.py` 已编码的正确性控制：在每个位置，缓存 logits 都在容许误差内等于完整重算。

接着使用同一个随机模型与固定批量，选择不超过 `max_len` 的上下文长度，例如 8、16、32、64、120。每个长度都对两条路径暖机，至少执行十次并报告中位数。记录：

- 以完整前缀重算下一个词元的毫秒数；
- 一个缓存解码步的毫秒数；
- `cache.nbytes()` 的缓存字节，以及公式 $2BLtd\,b$ 的结果；主干模型默认 float64 数组，所以 $b=8$；
- 加速比，以及置信区间或至少最小—最大范围。

**预测。** 完整重算会重复先前所有权重乘积与注意力工作。缓存解码重用先前的 $K,V$，但新 query 仍要注意全部 $t$ 个缓存位置；因此，缓存时间可能随 $t$ 成长。它应该长得比较慢，不是由数学保证维持平坦。

**失败结果的解读。** 在这个极小的 NumPy 尺度，串接、配置与解释器额外负担可能使缓存反而更慢。这不否定算术节省；它表示省下的 FLOPs 不是所度量的瓶颈。精确 logits 控制与计时结果都要报告。

## 实验 6.4——让缩放定律先预测，再解释

**问题。** 以五个较小宽度拟合的曲线，能否预测没看过的第六个宽度？

执行：

```bash
python spine/stage06_scaling.py --seed 0
```

脚本以相同词元预算训练宽度 8、12、16、24、32，拟合 $L(N)=E+AN^{-\alpha}$，并在训练宽度 48 **之前**，把该宽度的预测写入 `checkpoints/stage06_prediction.json`。下一次执行会覆写它，请先保存。

再以 `--seed 1`、`--seed 2` 重复；接着用 `--steps 1000` 对三个种子再做一轮。看过宽度 48 后重新拟合，不可再称为预测。每种条件记录预测 NLL、观察 NLL、带正负号的误差、种子分散与拟合的 $(E,A,\alpha)$。

**控制。** 固定语料切分、分词器、优化器调度、上下文长度与评估窗口。这里的“相同步数”表示训练词元数相同，不表示 FLOPs 相同；较宽模型会消耗更多计算。

**解读。** 检查误差是否与种子差异同量级，以及词元预算减半是否改变拟合指数或下限。只有五个含噪声的点时，即使插值看起来平滑，参数估计也可能不稳。一个预测失误是这次拟合与区间的证据，不是所有缩放关系都不存在的证据。

## 实验 6.5——配置固定计算预算

**问题。** 固定算术量下，应让小模型看更多词元，还是让大模型看较少词元？

选择宽度 8、12、16、24、32、48，并固定 $L,T,B$。对每个宽度，计算每词元矩阵乘积量

$$
c(d)=6N_{\text{mm}}(d)+12LTd,
$$

再配置 $D(d)=\lfloor C/c(d)\rfloor$ 个训练词元，换算成完整步数 $\lfloor D/(BT)\rfloor$。选一个让每个模型都有足够步数学习、整轮又负担得起的 $C$；查看损失前先写下 $C$。报告整数取整造成的未用余额。

至少训练三个种子，以误差棒画出留出数据 NLL 对宽度，并用实验 6.4 独立拟合的常数，把实证最小值与命题 6.2 比较。

**不要预先保证 U 形。** 玩具扫描可能单调或含噪声，因为候选宽度错过最优点、可分离拟合定律不佳，或小模型受优化限制。结论必须有条件：“在这些宽度、此语料、调度与预算下……”。如果某个宽度只分到几步，应放大 $C$，不可把未训练模型解读成缩放定律。

## 实验 6.6——用重算购买内存

**问题。** 丢弃区块内部状态能省下多少激活值字节，又要用多少额外时间购买这份节省？

另做一份实验用训练路径。基线版保留 `backward` 所需的每个数组；重算版只保留每个区块的输入与不可省的边界状态，丢掉内部注意力／MLP 数组，并在该区块反向传递前立刻重跑一次前向计算。

两条路径使用相同的 6 层参数与批量。计时前，先把损失与每个参数梯度和基线比较；报告最大绝对与相对误差。接着：

1. 以一套有文档说明、避免重复计算的规则，加总所保留激活数组的 `nbytes`；
2. 可另外度量程序峰值常驻内存，但要注明 Python 配置器可能保留已释放缓冲区；
3. 暖机后交替重复两种试验，报告每步时间中位数；
4. 计数额外的 `mm` FLOPs，不要先假定时间比例。

**预测。** 保留的激活字节应下降，FLOPs 与通常的墙钟时间则上升。精确比例取决于保留哪些边界，以及瓶颈是配置还是内存流量。若梯度有实质变化，你改变了计算，而不是实现检查点。若明确保存的字节下降但程序 RSS 没变，要区分活张量与配置器保留的内存。
