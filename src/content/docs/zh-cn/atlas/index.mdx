Atlas **不是百科全书**。AI 系统已经很会解释；它们无法可靠提供的，是*可以拿来检查它们的标准答案*。所以每个节点都是一个简短的**验证工具包（verification kit）**：

- 一段附关键方程的定义；
- 任何正确实现都必须满足的**不变量（invariant）**；
- 你可以手算复现的**已知数值（known value）**；
- **参考实现**与测试（若有对应的实验）；
- **常见错误**，以及每个错误由哪个不变量抓到；
- 以稳定的文献键引用的原始文献。

Atlas 也**不是**新概念的建议第一份解释。先在核心教材学动机与推导；写程序、审查 AI 答案或规划实验，需要精简检查时，再使用对应节点。短节点之所以可能显得突然，正因它是现场检查卡，不是章节。

## 使用节点的三个步骤

1. **先预测不变量。**阅读清单以前，先写一项任何正确实现都应满足的性质。例如，交叉熵下，$V$ 个结果的均匀预测器应得到 $\ln V$ nats。
2. **执行最小已知值。**先手算一个数字，再用程序复现。两者不符时，不要先扩大规模。
3. **刻意植入错误。**破坏一件事，确认所列不变量抓得到。从未失败过的测试，可能检查的是错误性质。

各区块角色不同：

| 区块 | 它回答的问题 |
|---|---|
| 定义／一段话 | 正在检查哪个对象？ |
| 不变量 | 在范围内的每个有效输入，哪些性质必须保持？ |
| 已知数值 | 哪个精确或近似精确数字能锚定实现？ |
| 常见错误／何时会说谎 | 何时看似合理的实现，甚至检查本身，会误导？ |
| 文献 | 机制或证据来自哪里？ |

“不变量”不表示离开节点假设后仍是普遍定律。例如，只有初始 logits 接近相等时，初始化损失才接近 $\ln V$；节点应说明这类条件。

节点以带类型的联系相连——*先修知识*、*相关*、*历史前身*、*替代机制*——只要任何链接、单元编号或引用键不存在，网站构建就会**失败**。Atlas 的上限约为 150 个节点；新增一个节点，通常意味着合并或淘汰另一个。

## 节点格式

```yaml
atlas:
  id: mech-attention            # (math|mech|arch|method|opt|para)-slug
  type: mechanism
  mastery: internalize          # internalize | understand-and-verify | access-on-demand
  core_units: [4, 5, 11]
  prerequisites: [math-softmax]
  related: [arch-transformer-block]
  predecessors: []
  alternatives: [mech-linear-recurrence]
  lab: labs/unit-04-attention   # 库中选用的验证工具包
  references: [vaswani-2017]    # src/data/bibliography.yaml 中的键
  last_reviewed: 2026-11-02
```

同样的数据也以 [`atlas.json`](/atlas.json) 的形式发布，供 AI 智能体与工具使用——见[机器可读的书](/zh-cn/mentor/machine-readable/)。节点的字段名称与 `id` 保持英文，以便与代码及英文版对应。
