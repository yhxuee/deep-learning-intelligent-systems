抽象问题若能反复回到同一个具体对象，通常会更容易思考。主干项目（spine project）是**一个你在整个核心教材中构建、扩充并探究的小型语言模型**。开始前不必先懂最后的 Transformer；在阶段 01，“模型”只是一张字符计数表。此后每个阶段一次只改一个观念，让你能问：新机制带来什么、付出什么代价，以及我们怎么知道它真的有效。

史丹佛大学的 CS336 证明了从零打造语言模型可以成为一门课的主轴 [CS336](/zh-cn/references/#cs336-2026)；主干项目把同样的想法缩小到笔记本电脑规模，使用一份精神上类似 TinyStories 的简单故事语料 [Eldan & Li 2023](/zh-cn/references/#eldan-2023)。

每个阶段都有一个**验证目标**——一个不依赖任何 AI、就能告诉你这个阶段是否正确的数字或不变量。所有目标都在 CI 中执行（`spine/test_spine.py`、`spine/test_model.py`）。

如果这是你的第一个机器学习项目，请依下列顺序阅读每个阶段：

1. 先写下预期会发生什么，以及一种可能的失败方式；
2. 阅读参考实现前，先执行最小的测试；
3. 实现或查看这一阶段唯一新增的机制；
4. 改代码前，先用文本解释每一个失败的不变量；
5. 记录通过的测试证明了什么——以及它**没有**证明什么。

所以红色测试不是对你的评判；在一个阶段的起点，它是问题的可执行叙述。

## 一个模型、一份语料

- **`spine/model.py`** 是一个 NumPy 写成的仅解码器 Transformer（前置层归一化、绑定嵌入、学习的位置、KV 缓存），其反向传递完全手写——也就是单元 03 与 04 的推导被实际执行。每个梯度都与中央有限差分比对，而一个植入计数器的矩阵乘积会计算 FLOPs，让单元 06 的 $6N + 12LTd$ 法则被验证到最后一个运算。消融与修补注意力头的接口供单元 11 使用。你可以用框架的自动微分写自己的阶段，再与这份参考实现比较。
- **`spine/data/tales.txt`** 由 `make_tales.py` 产生：1,400 个短篇故事、50 个不同字符，最后 140 个为留出数据。它是合成的，因此没有许可问题，而且**植入了标准答案**：刻意植入 67 组重复配对、6 个泄漏到训练数据中的留出故事、30% 错误的算术，以及只能靠复制才能预测的编造宠物名字，并把它们的位置写进 `tales_manifest.json`。后面的阶段必须检测或处理每一项。

## 各阶段

| 阶段 | 单元 | 你加入的东西 | 验证目标 |
|---|---|---|---|
| 01 | [01](/zh-cn/core/unit-01/) | 计数式二元语法、加 α 平滑 | 留出数据 NLL < $\ln V$；α → ∞ 恰好得到 $\ln V$ |
| 02 | [02](/zh-cn/core/unit-02/) | 绑定嵌入的分解式二元语法；神经 4 元语法 | 初始损失 $= \ln V$；查找梯度 = 独热梯度；可互换的符号合并；数据稀少时神经 4 元语法胜过计数 |
| 03 | [03](/zh-cn/core/unit-03/) | 以你推导的梯度训练的神经二元语法 | 初始损失 $=\ln V$；从上方收敛到计数最优值 |
| 04 | [04](/zh-cn/core/unit-04/) | 因果自注意力：Transformer 区块 | 每个参数的梯度检查；因果性；胜过二元语法 |
| 05 | [05](/zh-cn/core/unit-05/) | KV 缓存解码 | 缓存 logits = 完整重算；缓存字节 = 公式 |
| 06 | [06](/zh-cn/core/unit-06/) | FLOP 计算；五种宽度；缩放拟合 | 计数 FLOPs 恰好 $= BT(6N + 12LTd)$；拟合能还原已知定律；在第六次训练之前写下预测 |
| 07 | [07](/zh-cn/core/unit-07/) | MinHash 去重、污染检查、预训练 | 找到每一组植入的重复与泄漏，且没有移除其他东西 |
| 08 | [08](/zh-cn/core/unit-08/) | 采样器；二维流匹配 | 采样器在极限下彼此化约；精确高斯场把噪声输运到数据 |
| 09 | [09](/zh-cn/core/unit-09/) | 带 KL 锚定的 REINFORCE；DPO；奖励黑客稽核 | 估计量无偏；KL 正则化最优解 = 倾斜的参考分布；DPO 梯度 = 有限差分 |
| 10 | [10](/zh-cn/core/unit-10/) | 评估工具包 | 校准与失准预测器的 ECE；95% 自助法涵盖率；配对让区间变窄 |
| 11 | [11](/zh-cn/core/unit-11/) | 寻找、检验并消融复制电路 | 手工构建的归纳电路被每种方法找到；消融与修补的不变量 |
| 12 | [12](/zh-cn/core/unit-12/) | 预注册的消融与复现 | 确定性；可检测篡改的预注册；机械式的决策规则 |

## 执行

先在版本库根目录建立隔离环境，并安装一次共用的实验需求：

```bash
python -m venv .venv
source .venv/bin/activate          # Windows PowerShell：.venv\Scripts\Activate.ps1
python -m pip install -r labs/requirements.txt
```

接着进入主干目录执行：

```bash
cd spine
python -m pytest                         # 所有验证目标，笔记本电脑上几分钟
python stage01_bigram.py                 # 几秒
python stage04_attention.py              # 几分钟；写出 checkpoints/stage04.npz
python stage07_pretrain.py               # 约 15 分钟；写出 checkpoints/stage07.npz
python stage09_post_training.py          # 使用阶段 07 的检查点
```

每个阶段都只需要 NumPy。阶段 05 与 08–11 加载阶段 07 的检查点，它已提交进版本库，所以不需重新训练就能执行。要使用真实语料，对阶段 01–04 传入 `--data path/to/text.txt`。

第一次可先执行 `python stage01_bigram.py`，查看输出的均匀基线与留出数据损失，再用 `python -m pytest -k stage01 -v` 只跑相关测试。失败报告会给出测试名称、观测值与被违反的预期。编辑前，先把它翻成一句话，例如“平滑后的概率总和不再等于一”或“训练进步了，但留出数据的预测没有”。这句话就是诊断的起点。

产生的检查点与度量，只有在产生它们的条件下才算证据。请记录指令、代码版本、环境与随机数种子。通过单元测试只证明具名性质在测试案例中成立；它不会证明实现很快、能处理所有输入，或在另一份语料上也有科学用途。

## 设计规则

- **挣来的抽象。** 参考实现中的每个梯度都是你推导过的（单元 03–04）；一旦你能以它检查框架，就欢迎使用框架。
- **每个阶段只改一件事**，并在执行前写下预测。
- **笔记本电脑优先。** 每个阶段都能在笔记本电脑 CPU 上几分钟内跑完；不需要 GPU。
- **先有标准答案，再下结论。** 凡是阶段要检测某样东西（重复、污染、电路），都先植入或手工构建标准答案，让检测器本身也受到检验。
- **定位失败，不把它藏起来。** 保留第一个失败案例，尽可能缩成最小例子，修正机制，而不是放宽断言。
- **软件证据不等于科学证据。** 精确相等、有限差分检查或植入数据的回收，只能验证有限范围的主张。要推广到自然语料，必须另做研究。
